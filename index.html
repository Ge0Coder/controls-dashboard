Today's Knowledge Bite

The MQTT protocol, now ubiquitous in industrial IoT, was invented in 1999 by Andy Stanford-Clark (IBM) and Arlen Nipper (Arcom) specifically to monitor an oil pipeline across the desert over unreliable satellite links. The design goals — tiny code footprint, minimal bandwidth, and tolerance for intermittent connectivity — were pure process-control requirements, which is why it still fits so well on constrained PLCs and edge gateways 27 years later.

Engineering Curiosity

⚛

The PID controller predates electronics by more than a century: Elmer Sperry's gyroscopic ship autopilot in 1911 implemented proportional-integral-derivative action mechanically, using weighted linkages and dashpots to stabilise naval vessels against wave disturbances. The mathematical formalisation we teach today didn't arrive until Nicholas Minorsky's 1922 analysis of USS New Mexico's steering — and Minorsky derived the derivative term by watching helmsmen anticipate the ship's roll, essentially codifying human intuition as a transfer function. Every time you tune a loop, you're using a control law originally reverse-engineered from a sailor's reflexes.

Tech Spotlight

This week's spotlight is on the Model Context Protocol (MCP), the same technology that triggered the Siemens Mendix Studio Pro advisory. MCP is an open standard introduced by Anthropic in late 2024 that lets AI assistants connect to external tools, data sources, and applications through a standardised client-server interface. Vendors like Siemens are now embedding MCP servers into engineering tools so that an LLM assistant can read project files, query tag databases, or trigger build/deploy actions on behalf of an engineer. For controls engineers, the appeal is obvious: an AI that can actually interact with your PLC project, HMI tags, or Mendix low-code app, rather than just talking about them. The risk, as the Siemens CVE illustrates, is that MCP servers often run with the privileges of the engineering tool itself and may lack hardening typical of industrial protocols. A cross-site request forgery, an unauthenticated endpoint, or a prompt-injection-driven tool call can now map directly to project modification or code execution on an engineering workstation. Adoption challenges are considerable. Most MCP implementations today assume a trusted local environment (localhost only, single user), yet vendors are quietly exposing them over the network for team collaboration. Until there is an IEC 62443-style security profile for MCP — covering authentication, tool authorisation, and audit logging — treat any MCP-enabled engineering tool as you would an unauthenticated web service: segment it, restrict it to loopback where possible, and keep it off shared engineering VLANs.Read more →

Standards Watch

IEC 62443-4-2 (component security requirements) continues to gain traction as the de facto baseline for product certification, and vendors are increasingly listing Security Level (SL) ratings in datasheets. If you are specifying new PLCs, RTUs, or network devices for a 2027 project, it is now reasonable to require SL-2 as a procurement minimum and SL-3 for safety-adjacent functions. The companion IEC 62443-3-3 system-level requirements map neatly onto zone-and-conduit designs, so aligning your next network segmentation project to its Foundational Requirements saves rework later. NIST SP 800-82 Revision 3 (Guide to Operational Technology Security), finalised in late 2023, remains the most practical free reference for engineers asked to articulate OT security to IT auditors. It explicitly addresses safety interactions, deterministic performance constraints, and legacy device limitations — language that often wins arguments with IT teams who want to apply IT patch cadence to a DCS. Pair it with the ISA/IEC 62443 series when writing policy, since 800-82 Rev 3 cross-references 62443 extensively. Worth watching: ISA is progressing work on 62443-2-2 (security program ratings) which will give asset owners a way to benchmark their own cybersecurity maturity rather than just products. Early drafts suggest a scoring model similar to the C2M2 approach used in the US energy sector, which should make board-level reporting less of a dark art.Read more →

Incident of the Week

This week's incident is the newly disclosed Amazon report on China-linked actors using autonomous AI agents — dubbed 'Cairn' — to discover and exploit a zero-day in MONAI Label, a medical imaging software framework. While not strictly ICS, the methodology is directly relevant: the attackers delegated vulnerability research, exploit development, and initial access to an AI agent loop rather than human operators. Amazon's threat intelligence team observed the agents iteratively probing the target, generating exploit candidates, and refining them based on error responses — compressing a typical weeks-long research cycle into hours. The mechanism matters for OT because the same approach trivially applies to vendor-specific HMI web interfaces, engineering tool REST APIs, or obscure fieldbus gateways where the obscurity itself was previously a form of defence. An AI agent does not care whether a device has 50 users or 50,000; marginal cost per target approaches zero. Combined with the Siemens Mendix MCP advisory, we are seeing both sides of the AI-in-OT coin in the same week. Key lessons for controls engineers: first, 'security through obscurity' for niche HMI and engineering protocols is dying faster than expected — assume your bespoke vendor interface will be probed. Second, patch windows need rethinking; if attackers can go from CVE disclosure to working exploit in hours via AI, your 90-day OT patch cycle is a liability. Third, invest in detection at the behavioural layer (anomalous command sequences, unusual authentication patterns) rather than signature-based IDS, because AI-generated exploits will not match known signatures.Read more →

ICS / OT News Digest

CISA published a cluster of ICS advisories this week with direct relevance to plant floor engineers. Two large Siemens advisories cover the 'Node2Shell' vulnerability (CVE-2026-111497), a critical out-of-bounds write in the Brotli decoder bundled with Node.js that affects a wide swath of Siemens Industrial and Automation Software Products. Siemens Mendix Studio Pro also received an advisory for multiple flaws in its MCP (Model Context Protocol) Server that could allow remote attackers to execute tools or exfiltrate data by abusing a user's browser session — an early sign that AI-integration layers are becoming a new OT attack surface. Autonomy Logic's OpenPLC Runtime (<=4.2.4) has a race-condition vulnerability (CVE-2026-126088, CVSS 8.1) that allows creation of multiple unauthenticated admin accounts. Although OpenPLC is often seen in labs and education, it's increasingly used in small production deployments and research testbeds, so anyone running it should upgrade immediately. A more unusual advisory covers Elecbrakes trailer brake controllers (EB2, VM1, ELBC2000), where exploitation could let an attacker take control of trailer brakes, disable brake lights, or modify firmware — a sharp reminder that 'IoT-ified' safety-critical mobile equipment is now firmly in ICS-CERT territory. The libumqtt advisory (CVE-2026-125132, CVSS 8.6) affects an MQTT client library widely embedded in OpenWrt-based gateways and small industrial IoT devices. On the broader threat landscape, Amazon disclosed that China-linked actors used autonomous 'Cairn' AI agents to discover and exploit a zero-day in MONAI Label medical software — the first well-documented case of AI agents independently finding and weaponising a vulnerability. The European Commission also confirmed an AI-assisted cyberattack forced it to take services offline. For controls engineers, the takeaway is that vulnerability discovery is accelerating faster than most patch cycles, and attackers are no longer rate-limited by human analyst time. Separately, Norwegian energy firms were hit by cyberattacks this week; details remain thin but reinforce continued targeting of European energy infrastructure heading into winter.Read more →

CISA Vulnerability Digest

CISA's KEV additions this week include several items with likely OT exposure. Broadcom VMware vCenter (CVE-2026-123890) has an authentication bypass in the Directory Service — vCenter is pervasive in OT DMZs hosting engineering workstations, historians, and virtualised HMIs, and an unauthenticated network-reachable bypass should be patched or isolated this weekend. Cisco Expressway Series (CVE-2026-76466) contains hard-coded credentials allowing root command execution; Expressway often bridges corporate and plant collaboration systems. SAP NetWeaver Enterprise Portal (CVE-2025-42884) rounds out the enterprise trio and matters wherever MES/ERP integration touches plant systems. Several additions target developer and automation infrastructure increasingly found in OT support environments: Perforce Puppet Enterprise (CVE-2026-115731) deserialization, Apache Roller and Apache Axis RCEs, and BerriAI LiteLLM (CVE-2026-40217) — the latter notable as an AI gateway product being folded into operational toolchains. OpenSSH on Linux (CVE-2026-123158) has an authentication bypass that warrants urgent attention on any jump hosts or Linux-based gateways. Barracuda appliances (ESG, WAF, Load Balancer) received two entries including an auth bypass permitting malicious backup restore — review any Barracuda devices at the IT/OT boundary. Practical priorities for the plant: patch vCenter and any Linux OpenSSH exposed to the IT/OT interface first, verify Barracuda and Cisco Expressway firmware, and audit whether Puppet or LiteLLM sit anywhere in your engineering toolchain. For each, if patching requires a change window, compensate with firewall rules restricting management-plane access to a jump host.Read more →
