Today's Knowledge Bite

The MQTT protocol, now ubiquitous in IIoT and found in the libumqtt library flagged this week, was invented in 1999 by Andy Stanford-Clark of IBM and Arlen Nipper of Arcom specifically to monitor oil pipelines across satellite links. Its design goal was ruthlessly narrow — minimum bandwidth, battery-sippable, tolerant of intermittent connections — which is exactly why it then conquered everything from Facebook Messenger to smart thermostats two decades later. The "MQ" stood for IBM's MQ Series, though MQTT itself has nothing architecturally in common with it.

Engineering Curiosity

⚛

The PID controller as we know it was effectively reverse-engineered from a human helmsman. In the 1920s, Nicholas Minorsky was studying how experienced sailors held course on the USS New Mexico and noticed they corrected not just for current heading error, but for how fast the error was changing and how long it had persisted — proportional, derivative, and integral action, respectively. The mathematical formalism came after the observation, not before, which is why PID feels so intuitive once you have tuned a loop by hand: you are literally replicating what a competent human operator already does without thinking.

Tech Spotlight

This week's AI-agent exploitation story is a good prompt to look at agentic AI in engineering tools, flagged obliquely by the Siemens Mendix MCP Server advisory. MCP — the Model Context Protocol — is a fast-emerging standard for letting large language models invoke external tools and data sources. Vendors including Siemens, Rockwell, and several SCADA suppliers are embedding MCP servers into engineering IDEs so that an AI assistant can read tag databases, generate ladder logic, or query a historian on request. The practical upside is real: an engineer can ask "show me every analog input scaled outside 4–20 mA range in the last 24 hours" and get an answer without writing a query. The downside, visible in the Mendix advisory, is that MCP servers typically run as local HTTP listeners trusted by the browser and the IDE — meaning a malicious webpage or a CSRF-style attack can potentially drive engineering tools remotely. Early MCP implementations are repeating many of the same trust-boundary mistakes that plagued early OPC DCOM: implicit trust, weak authentication, and broad local privileges. Adoption-wise, expect this everywhere within 18 months. The guidance for now is to treat any MCP-enabled engineering workstation as a privileged asset: no general web browsing from it, strict egress filtering, and keep it on an isolated engineering VLAN until vendor hardening catches up.Read more →

Standards Watch

IEC 62443-3-2 (security risk assessment for system design) continues to gain traction as the de-facto bridge between engineering and security teams, and is now being cited in several EU NIS2 implementing guidance documents as an acceptable methodology for demonstrating OT risk management. For sites building zone and conduit diagrams for the first time, pairing 62443-3-2 with the Purdue reference model remains the pragmatic approach — the standard does not prescribe Purdue but it meshes cleanly with it. NIST SP 800-82 Revision 3, released in late 2023, is still the baseline most US-regulated sites reach for, and its mapping tables to the NIST Cybersecurity Framework 2.0 (which added the "Govern" function) are worth revisiting if your site's last gap analysis predates CSF 2.0. The CSF 2.0 Govern function explicitly calls out supply chain risk — directly relevant given this week's Siemens Node.js advisory, which is fundamentally a transitive dependency problem reaching OT via a JavaScript runtime bundled in engineering software. Finally, ISA/IEC 62443-4-2 component-level certification is showing up more often in procurement specifications. If you are writing RFQs for new PLCs, RTUs, or protocol gateways in 2027, requiring SL-2 or SL-3 certification as a gate rather than a nice-to-have is becoming defensible and increasingly common.Read more →

Incident of the Week

A useful case to revisit this week is the 2021 Oldsmar, Florida water treatment plant intrusion — not because it was sophisticated, but because every detail illustrates a controls engineering lesson. An attacker gained access via TeamViewer running on a plant HMI shared among operators with a common password, then briefly changed the sodium hydroxide setpoint from roughly 100 ppm to 11,100 ppm. An alert operator saw the mouse cursor move and the setpoint change, and reverted it within minutes. Later analysis suggested the risk was partially mitigated by downstream pH monitoring that would have alarmed before chemically altered water reached consumers, but the proximity to harm was uncomfortable. The root causes were a stacked set of ordinary engineering oversights: unsupervised remote access software installed for operator convenience, shared credentials, no MFA, Windows 7 past end-of-support, and a flat network with no segmentation between the HMI and the public internet. None of it required a nation-state actor. Three lessons for controls engineers: first, inventory every remote-access tool on every HMI and engineering workstation — including the ones installed informally by integrators or vendors during commissioning. Second, assume operators will not notice intrusions; rely instead on process-layer safeguards (independent high/high alarms, hard limits in PLC code, downstream analytical interlocks) that make unsafe setpoints physically impossible or immediately detectable. Third, change control for setpoints matters: log every setpoint write with source identity, and alarm on out-of-band changes.Read more →

ICS / OT News Digest

CISA released a notable batch of ICS advisories this week with direct relevance to engineering environments. Autonomy Logic's OpenPLC Runtime (versions 4.2.4 and earlier) contains a race condition in account creation that permits multiple unauthenticated admin accounts to be created — a concern given OpenPLC's widespread use in education, research labs, and some small-scale production deployments. Any internet-exposed OpenPLC instance should be isolated immediately pending patching. Two Siemens advisories cover the widely-publicised Node.js "Node2Shell" Brotli decoder vulnerability (CVE-2026-111497), impacting a broad swath of Siemens Industrial Software and Industrial Automation Software products. This is an out-of-bounds write enabling potential remote code execution via memory corruption. Siemens is rolling out updated versions; engineering workstations running SIMATIC and TIA Portal ecosystems should be reviewed against the advisory list. A separate Mendix Studio Pro advisory covers multiple MCP Server vulnerabilities enabling cross-site request forgery and unauthorised tool execution — an early warning that AI tooling embedded in engineering IDEs is now part of the OT attack surface. Of particular interest to mobile and transport-adjacent engineers, Elecbrakes electronic trailer brake controllers (EB2, VM1, ELBC2000) have severe vulnerabilities allowing an attacker to take control of trailer braking, modify firmware, and disable brake lights or safety interlocks. The libumqtt MQTT client library (≤1.1.1) also has an integer underflow (CVSS 8.6) that could enable DoS or memory corruption in MQTT-based telemetry stacks common in IIoT gateways. On the broader cyber front, Amazon disclosed that China-linked actors used autonomous "Cairn" AI agents to discover and weaponise a MONAI Label zero-day — the clearest public example to date of AI-driven offensive tooling finding real exploitable bugs in operational software. Norwegian energy sector cyberattacks also featured in weekly roundups, reinforcing that energy infrastructure remains a priority target heading into winter.Read more →

CISA Vulnerability Digest

The most OT-relevant KEV additions this fortnight centre on virtualization and network edge infrastructure that typically sits underneath or adjacent to OT networks. CVE-2026-123890 in VMware vCenter is an authentication bypass in the Directory Service reachable by any attacker with network access to vCenter — and vCenter commonly hosts SCADA historians, HMIs, and engineering VMs in converged data centres. Patching or network-segregating vCenter management interfaces should be treated as urgent. CVE-2026-76466 in Cisco Expressway Series is a hard-coded credentials flaw enabling remote root execution; while Expressway is primarily a collaboration product, it is often dual-homed into corporate zones that touch OT DMZs. Two Barracuda entries (CVE-2026-111560 OS command injection across ESG/WAF/ADC/etc., and CVE-2026-116606 ESG authentication bypass via config import) matter because these appliances often front OT-adjacent email and web traffic. Also notable is CVE-2026-115731 in Puppet Enterprise — a deserialization RCE triggered by any CA-signed agent certificate, which is directly relevant to industrial sites using Puppet to manage engineering workstation or server fleets. Finally, CVE-2026-123158 (OpenSSH on Linux authentication bypass) warrants immediate attention on any jump hosts and Linux-based gateways in OT. Practical remediation priorities: patch vCenter and Expressway first, review Puppet master exposure, then roll Barracuda and OpenSSH updates through change control. For KEV items without immediate patch windows, apply compensating controls at the firewall — restrict management plane access to named jump hosts only.Read more →
